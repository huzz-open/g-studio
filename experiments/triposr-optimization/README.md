# TripoSR 优化实测 · 2026-10-26

**结论：能减轻表面噪声，但这三张图的错误三维结构没有被这些优化纠正。只升网格分辨率无明显结构收益；保守网格后处理更实用，过强平滑会损坏细杆和碎片。**

本轮选择先验证现有 TripoSR 优化，而非再安装另一套大型模型。所有推理在本机 CPU 离线完成，保留官方网络/权重，沿用已验证的 CPU Marching Cubes 适配。没有调用外部 AI 或生成新的参考图片，也没有接入 Web。

## 打开结果

双击 `view-results.cmd`。可选择三件物品和十种设置，旋转观察、开启地面阴影。模型显示为纯色，避免颜色纹样掩盖几何问题。

本次结果目录：`results/20261026-175658/`。

- `candidate-comparison.png`：原始与保守候选，分别展示正面和侧面。
- `overview.png`：原始、官方默认方案、输入模糊、中/强平滑的正面对照。
- `umbrella-all.png`、`vase-all.png`、`chair-all.png`：全部设置的正面、侧面、低位光源阴影。
- 各物品/方案目录含 `mesh.glb`、`raw.glb`、四方向纯色图、两个光源高度的投影图、参数与指标 `result.json`。
- `results.json`：全体 30 份结果的参数、耗时和检查。

`mesh.glb` 用于观察，`raw.glb` 保留模型坐标。为了不隐藏平滑导致的收缩，同一物品所有结果共用原始模型的比例尺，只重新居中和落地，不把每个结果再次拉伸到同样大小。

## 实验设计

三张输入仍为此前的油纸伞、花瓶、椅子。共 12 次神经网络推理；网格提取和平滑复用其结果，最终每张图有 10 份网格，共 30 份结果。

| 方案 | 改变了什么 |
|---|---|
| 原方案 96 | 复现此前 512×512 最近邻缩放输入、MC 96、密度阈值 25 |
| 仅网格升至 256 | 同一场编码，仅提高网格提取分辨率 |
| 官方预处理 96 | 原生 RGBA 按官方 `resize_foreground(..., 0.85)` 裁切和填充、合成灰底，交给官方预处理器缩放；MC 仍为 96 |
| 官方预处理＋256 | 官方预处理与官方默认 MC 分辨率 256 的组合 |
| 输入高斯模糊 2px | 对原方案的 RGB 模型输入施加半径 2 像素高斯模糊；MC 96 |
| 前景约 70% | 同样最近邻处理，前景最长边从 434 调为 358 像素；MC 96 |
| Taubin 20 步 | 原 96 网格后处理，lambda=0.5，nu=0.51，共 20 次交替迭代 |
| Taubin 80 步 | 同上，迭代 80 次 |
| Taubin 320 步 | 检查 80 步仍有大起伏后追加的强平滑压力测试 |
| 保守后处理候选 | 按本次检查结果选择：去小碎片，花瓶平滑 80 步，伞/椅子平滑 20 步 |

首轮基线对旧结果检查了面数和顶点坐标（误差容限 1e-5），三件均复现。单独平滑的结果保持原三角形连接顺序不变；保守候选明确记录了删除的碎片，不把这些删除伪装成 AI 重建能力。

## 结果

### 提高分辨率

| 物品 | 原 96 面数 | 仅提高到 256 | 官方预处理＋256 |
|---|---:|---:|---:|
| 油纸伞 | 6,096 | 48,288 | 49,320 |
| 花瓶 | 15,476 | 128,384 | 135,016 |
| 椅子 | 13,540 | 100,566 | 88,464 |

提高采样密度保留了更多细纹和起伏，未消除花瓶表面噪声，也未纠正伞面竖立薄片。96 提取约 1–1.8 秒（个别受负载影响约 4.3 秒），256 约 21–23 秒。神经网络推理另计，本次约 12–31 秒。

这说明此前的低网格分辨率并不是三维形状错误的唯一原因。官方预处理与 256 默认分辨率已经实际跑过，不能再把问题简单归因于最近邻预处理这一项。

### 输入处理

官方预处理、模糊和缩小前景占比都会改变形状与姿态，但三张样例没有得到统一稳定的改进。模糊可压低部分细纹，也会改变轮廓和细部；缩小前景后的伞出现更明显倾斜，仍没有恢复正确的展开伞面。

这不是对所有输入图的结论，仅表示这次几个具体设置没有解决当前素材的问题。

### 网格平滑

Taubin 平滑能降低高频表面起伏，花瓶最容易看出变化。但花瓶的侧面压扁/倾斜、伞面的错误方向仍然存在。平滑后的错误模型仍是错误模型。

过强平滑有实测损失：

- 在统一坐标的 Z=0.8 截面，伞杆 X 宽度由约 0.0653 变为 0.01224，只剩约 **19%**；Y 宽度由 0.0897 变为约 0.00954。
- 原花瓶包含 36 个连通壳，很多是很小的碎片。直接平滑 80 步后出现 208 个近退化面，320 步后有 328 个（归一化三角形面积 < 1e-12）。
- 椅子的镂空投影也变化：固定正面 256 像素诊断下，包围孔洞总面积从 1,864 像素增至强平滑后的 2,527 像素。它是形状变化量，不是质量分数。

因此不建议给所有物体统一套用很强的平滑。

## 保守候选

这不是重新训练或重新理解图片，而是我根据本次结果选择的后处理配置：

- 花瓶：删除表面积低于整体 0.5% 的独立小壳，共 35 个、392 面，占总表面积约 0.314%；保留主壳后平滑 80 步。
- 伞和椅子：该清理规则没有删除构件，只平滑 20 步，以减少细杆损失。
- 三个候选都再次检查有限坐标、近退化面和导出；本次均无近退化面。
- 平滑本身约 0.03–0.13 秒，不含网格读取、导出和渲染。

候选文件：

- `results/20261026-175658/umbrella/candidate/mesh.glb`
- `results/20261026-175658/vase/candidate/mesh.glb`
- `results/20261026-175658/chair/candidate/mesh.glb`

候选只改善外观噪声，仍需检查几何结构。删除小连通壳的规则仅针对这批样例选择，不能不检查就用于含独立小配件的新物体。

## 后续模型选择

本轮没有对其他模型宣称实测效果。进一步查阅官方资料后发现 [Stable Fast 3D](https://github.com/Stability-AI/stable-fast-3d#cpu-support) 明确提供 CPU 后端，比只支持 CUDA 的方案更值得在这台机器上考虑；但其[官方权重获取流程](https://github.com/Stability-AI/stable-fast-3d#requesting-access-and-login)要求 Hugging Face 授权访问，Windows 支持也标为实验性，本轮未下载或运行。

[Hunyuan3D-2 的形状推理代码](https://github.com/Tencent-Hunyuan/Hunyuan3D-2/blob/main/hy3dgen/shapegen/pipelines.py)可指定设备和精度，表面提取也提供 CPU scikit-image 路径；这只能说明有适配方向，尚不能代替本机安装、内存和运行耗时验证。

对当前项目，已有实验更支持“可编辑程序化几何作为可靠起点；神经重建网格作为需审核的候选”的路线。
