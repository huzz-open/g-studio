# Codex / DSH / TripoSR 三方对比

## 查看

双击 `view-results.cmd`，在独立桌面评审器中切换 Codex、DSH、TripoSR。默认是原生高分辨率显示；可打开“像素放大显示”对照此前的低分辨率观感。观察表面时建议选择纯色并关闭阴影。

- `results/three-way.png`：三件物品的三方几何与阴影总图。
- `results/vase-surface-detail.png`：原生 640 像素、纯色、无阴影的瓶体对照。
- `results/<物品>/<来源>/views.png`：四方向结果。
- `results/<物品>/<来源>/geometry-normal.png`、`geometry-depth16.png`：几何法线、16 位相对深度的诊断图。
- `results/metrics.json`：源文件、转换、面数、轮廓比较指标。
- `models/codex-*.glb`：从此前真实模型代码直接导出的几何。

## 我的模型如何生成

Codex 当时是根据图像和物品常识编写程序化几何代码，并在此前对话中做过调整：

| 物品 | 代码表示 | 原始三角面数 |
|---|---|---:|
| 油纸伞 | 48 分区圆锥薄壳＋16 分区圆柱伞杆/顶盖 | 320 |
| 青花瓷瓶 | 若干“半径、高度”轮廓点绕竖轴旋转，圆周 24 分区 | 576 |
| 靠背椅 | 座面、椅腿、扶手、横梁和中央板组成的盒体 | 144 |

图片中的花纹没有被刻进三维表面。原画负责最终像素外观，几何主要提供空间位置、遮挡和阴影。

这与 DSH “看图理解结构、写代码”的路线相近。TripoSR 则通过固定的神经网络预测三维场，再提取三角网格，不会像这段程序一样明确规定“瓶身必须旋转对称”。

## 提取方式与对比边界

`export-codex.cjs` 直接调用已有 `model.ts` 的 `buildItem()`，没有重新设计或美化形状。三个原始 TypeScript 文件完整保存于 `codex-source/`，来源路径与 SHA256 在 `codex-raw.json` 和 `results/metrics.json` 内。

导出仅进行了右手坐标转换 `(x,y,z) → (x,-z,y)`（原来的 Y-up 转 Z-up）、平移居中、统一缩放使最长边为 2。保留三角面数量和位置关系，验证 GLB 往返顶点误差在 2e-7 内。保留原始面法线，没有额外平滑几何。

三者统一使用正交投影、20° 俯角、相机左前方 45° 的光源、45° 光源高度、相同材料及渲染器。因为输入模型各自的正面朝向不同，在 15° 步长下找最佳二维轮廓方位，再展示同方向及侧背面。桌面版只旋转显示副本以统一朝向，不修改磁盘模型。

**这不是同条件的一轮模型能力排名。**Codex 模型经历此前交互调整；DSH 是一次提示词的首轮代码；TripoSR 是固定参数推理。此处比较实际产物及三种表示方法的特点。

## 观察与限制

- **Codex：形状简洁、计算量低，但细节最少。**伞面是圆锥形，缺少 DSH 的伞骨、握把和流苏；瓶子有明显分段棱面，瓶内只是瓶口附近的浅腔；椅子中央板为实心，没有雕花孔洞。
- **Codex 旧椅子也有连接问题。**中央板底部为 1.03，座面顶部为 0.94，有 0.09 的间隔；中央板顶部为 2.01，顶横梁底部为 2.06，有 0.05 的间隔。归一化后分别约 0.0804 和 0.0446。此前模型是阴影演示用的简化代理，不能假定其结构完全准确。
- **DSH：比我的旧模型细致，瓶子显示更圆滑。**它有更多轮廓点、64 圆周分区和插值法线，也明确构建了更完整的内腔；椅子的简化格栅和连接缝问题仍存在。
- **TripoSR：在原生高分辨率、纯色、关闭阴影的条件下，瓶身依然有明显多余表面起伏。**几何法线/深度来自网格而非颜色贴图，因此这些起伏不能全部归因于纹理或像素放大。可能包含网络把图像纹样、明暗理解成形状的误差，以及密度场/网格提取产生的噪声；本次没有做训练或预处理消融，不能精确分摊原因。
- 此前像素预览确实会放大台阶和锯齿。高分辨率可以减少这层显示影响，不能消除已有网格中的凹凸、压扁或错误背面。

“更圆滑”也有不同含义：增加分段、改法线可减轻程序化模型的棱面感；平滑算法可减弱网格噪声，但可能损失细杆、孔洞和轮廓，且无法可靠纠正整个伞面方向错误。没有在本次比较中替任何一方做这种后处理。

## 面数与二维轮廓

| 物品 | Codex 面数 / IoU | DSH 面数 / IoU | TripoSR 面数 / IoU |
|---|---:|---:|---:|
| 油纸伞 | 320 / 0.772 | 4,152 / 0.805 | 6,096 / 0.865 |
| 青花瓷瓶 | 576 / 0.863 | 5,888 / 0.867 | 15,476 / 0.936 |
| 靠背椅 | 144 / 0.656 | 324 / 0.524 | 13,540 / 0.720 |

IoU 仅表示某个投影方向经居中缩放后的轮廓吻合程度，不能代表三维结构、表面平整度或阴影正确性。

## 复现

从项目根目录执行：

```powershell
node experiments/geometry-comparison/export-codex.cjs
experiments/triposr-local/.venv/Scripts/python.exe experiments/geometry-comparison/compare.py
```

导出脚本默认读取此前 `props-lighting-review` 工作树，也可用第一个参数指定源工作树。重新执行会更新本目录的源码快照及对比结果。没有修改 Web 或原始 Codex/DSH/TripoSR 模型。
