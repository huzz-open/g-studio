# 文档写作规范

[开发指南](../../CONTRIBUTING.md) · [文档索引](../README.md)

文档按读者任务组织。当前行为、设计理由和历史证据分别维护，避免同一事实在多个页面反复追加。

## 内容归属

| 内容 | 位置 | 写作重点 |
| --- | --- | --- |
| 项目介绍 | 根目录中英文 README | 用途、主要能力、最短启动路径、必要链接 |
| 目录入口 | 子目录 README | 本目录职责、最短使用方式、专题导航 |
| 用户操作 | `docs/guides/` | 前提、步骤、结果、常见失败处理 |
| 当前技术约定 | `docs/reference/`、协议包文档 | 字段、边界、源码入口 |
| 部署与配置 | 对应服务目录 | 启动、配置、网络、缓存和排错 |
| 开发流程 | `docs/development/` | 环境、验证方法和维护约定 |
| 设计方案 | `docs/design/` | 目标、理由、取舍、实施状态与开放问题 |
| 验证与调查 | `docs/history/` | 日期、版本、条件、结果、限制和复现入口 |

## README

根 README 建议控制在约 60 行内，中英文保持结构与事实一致。默认快速开始使用网页启动命令，可选 AI 单独说明首次下载成本，并链接详细指南。

子目录 README 保持入口职责。较长的部署参数、设计论证或验证说明放入同目录专题文件。性能表、开发过程、修复流水账与临时截图路径不放进 README。

## 格式

- 每页一个一级标题，标题层级连续；普通标题不添加手工章节编号；成组的顺序设计稿和历史快照可保留原编号。
- 标题、列表、表格和代码块前后留空行；不要用分隔线重复划分已有标题的章节。
- 命令注明执行目录与环境；代码块标注 `sh`、`powershell`、`ts`、`json` 或 `text` 等语言。
- 表格用于比较、字段和参数；连续说明使用短段落，操作过程使用有序列表。
- 本地文档使用相对链接和有意义的标题，链接到具体章节时检查锚点。代码位置优先链接仓库文件。
- 使用 UTF-8、LF 换行，文件结尾保留一个换行；不对普通段落强制固定列宽。

## 状态与维护

设计开头写明已接入、部分实施或待实施。历史记录写明日期、版本和测试条件；历史中的“当前”仅指当时版本。功能变更先更新当前说明，再补充历史证据，不能靠在文末追加更正维持两套相反结论。

已过时但有追溯价值的结果保留在历史区，并链接替代它的当前说明。保留原始失败和受限结论，不把文件生成成功、模拟测试通过或局部硬件实测写成完整验收。

文档写给没有参与开发讨论的读者。删除会话指代、执行过程汇报和未经验证的完成声明；机器私有产物标注为本地证据，不作为仓库必需文件。

新增或移动文档时同步分类索引与所有入站链接。一个事实只在所属专题详细维护，其他页面通过链接引用。
