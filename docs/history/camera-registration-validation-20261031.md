# 相机—模型配准：有真值的编码验证（2026-10-31）

本轮目标是检验“保持模型形状和世界姿态，通过改变相机观察角度、尺度及图像平移实现配准”的假设。不是发布新的生产优化算法。实验代码位于 `src/modules/experiments/registration/camera-registration.ts`，没有修改生成任务、资产数据或现有优化入口。

## 验证结论

1. 在原模型与参考图严格一致、正交投影、模型上方向已知、相机无滚转的情况下，相机参数搜索可以恢复很准确的投影。12 个精确合成案例的轮廓 IoU 中位数为 0.9887，独立留出点的投影 RMS 中位数为 0.473 像素。
2. 仅靠轮廓仍会得到错误的对应关系。带小凸起的薄片案例 IoU 为 0.987，但同一几何点的投影 RMS 为 120.61 像素。这说明不能按平均 IoU 宣称算法已经解决配准。
3. 给定正确二维—三维对应点时，相同相机假设下的参考求解器，在 12 个精确合成案例上留出点 RMS 最大为 0.0268 像素。这验证了求解过程；没有验证自动特征匹配，因为对应点来自合成真值，部分点在真实图像中可能不可见。
4. 对项目已有的真实生成伞模型，相机搜索 IoU 达到 0.934，高于现有姿态拟合的 0.842，但选择了约 -31.39° 俯仰角。深度测试后的网格预览确认这是从下面看伞。加入所有资产共用的 0°～85° 俯视约束后，得到约 +30.92°、IoU 0.934 的伞面视图，不改变模型几何。两种解的轮廓分数几乎相同，显示相机观察域约束具有实际作用。
5. 摄像机旋转和相对模型旋转在图像中可以完全等价。单元测试直接验证了矩阵关系；正交投影下沿视线移动模型也不改变投影。这一实验只求二维投影映射，不声称恢复世界深度、支撑面或物理尺度。

因此，相机配准是假设明确时可行的求解方式，但“换成旋转相机”不能单独消除歧义。当前结果不支持用这个轮廓原型直接替换生产算法。

## 对照方法

| 方法 | 输入信息与约束 |
|---|---|
| initial | 默认 20°/25° 相机，使用目标边界初始化统一尺度与平移；不是完全未对齐的原始屏幕截图 |
| legacy | 当前 `findOrientation`：完整旋转搜索、尺度/平移、可见表面保留约束；本实验不运行后续网格修复 |
| camera | 模型坐标不变，搜索相机 pitch/yaw、统一尺度和画面平移；没有相机滚转，没有可见面保留筛选 |
| cameraAbove | 与 camera 相同，但所有输入统一限制相机俯仰角为 0°～85°；这是一项明确的俯视场景假设，不是物品分类规则 |
| oracle | 已知二维—三维对应点；对每组角度解析消去尺度和平移，再多起点搜索角度 |

两种轮廓方法的目标均由 IoU 与双向轮廓距离组成，使用 48/80/160 的搜索分辨率；搜索维度、预算和可见面约束不同。因此不能把两者的差异全部归因于相机参数化。本轮未验证联合多资产的共享相机拟合，也没有实现可靠的自动对应点提取。

补充观察域对照保留了全部 20 个案例。正俯视约束对薄片仍给出 IoU 0.994、留出点 RMS 120.24 px，说明它没有解决前后表面对应。真值为 -25° 的案例故意违反该约束，IoU 从 0.983 降到 0.750；不能把错误的先验当成通用正确性保证。

候选代码不读取物品名称、类别或模型供应商。全部案例使用相同搜索参数；没有对失败案例调参。12 个精确案例来自六种程序化结构，随机组合体使用不同固定种子，均不调用项目六个内置物品的几何构造器。真实素材与合成真值实验分别统计。

## 数据与边界条件

共 20 个案例：

- 12 个精确正交案例：随机非对称组合体、贯通孔、薄杆悬空罩、旋转对称体、薄片和桥形结构；俯仰角包含 -25°、8°、12°、20°、25°、35°、40°、50°、55°、60°、78°，并改变方位和图像位置。
- 4 个假设边界案例：像素化、局部遮挡、透视输入、模型比例不匹配。它们不是假装符合正交假设的成功样例。
- 4 个已有生成模型及其原始图片：伞、桶、椅子、盆景。图片 SHA-256 与生成清单的 `inputSha256` 核对；报告保存网格与图片哈希。这些没有真实相机/姿态标注，不报告姿态准确率。

目标图片由独立的重心坐标光栅器产生，搜索使用扫描线光栅器。合成目标不调用待测配准函数；光栅器一致性另有测试。生成式图片不能提供精确相机真值，所以本轮没有调用生图或重新启动模型推理：已知相机的程序渲染用于检验数学正确性，已有生成网格用于检验实际输入误差。

## 指标及实测值

所有方法最终在同一个原始图像画布上独立重新投影、计算 IoU；不会把各自预测再次居中后才计算分数。对应点训练/验证按不同顶点划分；验证点不参与 oracle 拟合。

| 12 个精确合成案例 | 固定角度 | 现有拟合 | 相机搜索 | 已知对应参考解 |
|---|---:|---:|---:|---:|
| IoU 中位数 | 0.5594 | 0.9697 | 0.9887 | 0.99985 |
| 留出点 RMS 中位数 / px | 32.59 | 14.42 | 0.473 | 0.0183 |
| 留出点 RMS 最大值 / px | 65.32 | 105.87 | 120.61 | 0.0268 |

上述 RMS 是同索引几何点误差，不是对称性等价下的姿态指标。旋转对称体的方位歧义不能据此判为失败；报告显式标记该案例。薄片也存在单视图前后表面歧义，所以其大 RMS 证明的是“高轮廓重合不保证正确对应”，不是仅凭这些输入就一定能选出唯一朝向。

| 真实生成素材，无角度真值 | 固定角度 IoU | 现有拟合 IoU | 相机搜索 IoU | 相机搜索俯仰角 |
|---|---:|---:|---:|---:|
| 伞 | 0.633 | 0.842 | 0.934 | -31.39° |
| 桶 | 0.935 | 0.977 | 0.980 | 28.67° |
| 椅子 | 0.870 | 0.920 | 0.919 | 22.26° |
| 盆景 | 0.841 | 0.907 | 0.906 | 20.36° |

统一正俯视约束下，伞/桶/椅子/盆景 IoU 分别为 0.934/0.980/0.917/0.906，角度约为 30.92°/28.81°/22.11°/20.17°。这些是每资产独立拟合结果，不代表四个资产已经能共享同一相机严格重合。

这些指标不包含阴影、碰撞或完整图像纹理匹配。特别是伞的较高 IoU 不能掩盖负俯仰角问题。主实验原始模型顶点在每次实验前后做哈希检查，确保配准不破坏几何。

## 复现与产物

在仓库根目录运行：

```powershell
npm run test:registration
npm run verify:registration
node scripts/registration/mesh_previews.cjs output/registration-validation-20261031
python scripts/registration/render_report.py output/registration-validation-20261031
```

仅运行程序化案例：

```powershell
node scripts/registration/verify.cjs output/registration-synthetic --synthetic-only
```

依赖现有 Node/TypeScript 环境及 Python 的 Pillow、NumPy；不需要模型服务、GPU、网络或额外账号。完整验证约两至三分钟，取决于 CPU。

结果保存在被 Git 忽略的 `output/registration-validation-20261031/`：

- `report.json`：每个案例的相机参数、完整投影矩阵基向量、误差、备选角度、耗时和输入哈希。
- `report.html`：逐案例原图和叠加结果。
- `comparison.png`：全部结果；`summary.png`：重点成功和失败案例。
- `*-mesh.png`、`*-blend.png`：真实输入的深度测试网格预览与原图叠加。位置和尺度沿用求解结果，不再重新适配。
- `*-target.rgba`、`*.mask`：可独立复核指标的像素结果。

白色表示重合，蓝色为预测遗漏，红色为预测超出。报告保留全部失败案例，不以自动回退隐藏问题。

下一步实验应检验可由实际输入得到的对应点、结构边缘或可见面证据，能否排除当前歧义；应与本轮 oracle 上界明确区分。尚不能把“用户不需要提供信息”与“算法已经恢复唯一正确姿态”混为一谈。
