# 四方向角色视频素材制作工作流

版本：v1，2026 年 10 月 23 日。状态：制作流程方案，非已交付功能说明。返回[文档索引](../README.md)。

从一套经过人工确认的四方向静态 Idle 立绘出发，每种动作优先生成一条包含四个方向的视频，再提取游戏动画。暂不额外绘制或生成动作关键帧，不制作 Idle 变体，不安排独立 Start 和 Stop 视频任务。

第一轮交付四方向静态 Idle、Run 循环和动画描述文件。同源视频中可用的短收步，经匹配验收后附带交付；没有合格收步也可以完成基础版本。本文规定制作和验收方法，不表示 G-Studio 已实现全部步骤。

## 固定制作规则

| 项目 | 规则 |
| --- | --- |
| 方向顺序 | down 下、right 右、up 上、left 左 |
| 方向含义 | 下为面向屏幕下方，上为背向屏幕上方；左右均按角色实际朝向描述 |
| 视角 | 固定为已经确认的游戏俯视角度，与地图协调 |
| Idle | 每方向一张标准站姿，可以双脚并拢 |
| Run 和 Walk | 保持自然步态，不强制包含 Idle 姿势 |
| 换方向 | 瞬间切换，移动中保留步态进度，不播放转身 |
| 移动响应 | 有移动输入立即响应；输入归零的当帧停止世界位置移动 |
| 收步 | 只播放不产生根位移的短落脚或回正；不等待下一圈，不原地继续跑步 |
| 动画位移 | 角色世界位置由游戏逻辑控制，视频中的人物漂移不能作为移动距离 |
| 失败处理 | 外观或动作不合格就重选或重生；不能用插帧掩盖结构错误 |

“动作”与“方向”分开管理。例如 action=run、direction=up 选择向上的跑步动画，不为换方向增加一套玩法状态。

## 制作四方向 Idle 基准

输入角色立绘，通过绘画工具生成并修改四方向游戏视角站姿。人工确认后保存四张独立 PNG，同时制作一张总览供比较。

| 文件 | 内容与用途 |
| --- | --- |
| idle/down.png | 正面朝下，作为下方向外观基准和静态 Idle |
| idle/right.png | 朝屏幕右侧，作为右方向基准 |
| idle/up.png | 背对镜头朝上，作为上方向基准 |
| idle/left.png | 朝屏幕左侧，作为左方向基准 |
| idle/review-sheet.png | 四方向总览，只供 review，不默认上传为视频首帧 |

通过条件：角色身份、身体比例、视角和画风一致；衣服、剑、葫芦等装备位于正确身体侧；画布尺寸、缩放和地面参考点统一。不能用镜像替代带有非对称装备的另一方向。

冻结为 character_v1。后续所有动作引用这一版本，不把未经 review 的视频截图自动升级为新基准。

保留透明 PNG 作为正式 Idle。视频输入若需要纯色背景，另外导出相同构图的纯色副本，不改变角色比例。绿幕与服装撞色时换用合适背景，并沿用到同一批任务；不能把角色身上的绿色直接当作背景删除。

## 参考图怎么传

### 默认使用多图参考模式

上传四张独立方向图，顺序固定，并在任务记录中保存对应关系。

| 上传顺序 | 参考名称 | 用途 |
| --- | --- | --- |
| 图片 1 | down | 下方向的外观、视角与站姿参考 |
| 图片 2 | right | 右方向参考 |
| 图片 3 | up | 上方向参考 |
| 图片 4 | left | 左方向参考 |

在网页工具中，把它们添加到“参考图片”入口。提示词中的图片名称应替换成平台实际显示的引用标记，例如“图片 1”或平台生成的图片标签。文件名本身不保证模型能识别引用关系。

通过 API 提交时，将四张图作为独立图片内容项，使用所选接口的 reference_image 角色。图片地址应为平台支持的上传资产标识、可访问 URL 或编码数据；本机磁盘路径不能直接当作远端图片 URL。

以下为 MiniMax H3 官方接口形式的请求体示意。替换模型名、提示词和四个图片地址，并按实际接口校验参数后提交；这不是 G-Studio 当前已有的调用代码。

```json
{
  "model": "MiniMax-H3",
  "content": [
    { "type": "text", "text": "替换为下一节的完整 Run 提示词" },
    { "type": "image_url", "image_url": { "url": "<DOWN_IMAGE_URL>" }, "role": "reference_image" },
    { "type": "image_url", "image_url": { "url": "<RIGHT_IMAGE_URL>" }, "role": "reference_image" },
    { "type": "image_url", "image_url": { "url": "<UP_IMAGE_URL>" }, "role": "reference_image" },
    { "type": "image_url", "image_url": { "url": "<LEFT_IMAGE_URL>" }, "role": "reference_image" }
  ],
  "duration": 12,
  "resolution": "768P"
}
```

这个示例选择参考模式，不额外混入 first_frame 或 last_frame。接入其他平台时保留四方向对应关系，字段按该平台适配。[MiniMax 官方视频生成指南](https://platform.minimax.io/docs/guides/video-generation)

### 参考图与首尾帧的区别

四张参考图提供角色与方向信息，不等于四个被锁定的时间关键帧。每方向的站姿、运动和回站姿在本方案中由提示词组织，并通过结果验收。

如果当前工具只有整条视频的首尾帧入口，不能把四张图塞进同一首帧位置，也不能声称一对首尾帧锁住了四个方向。应切换到支持四张参考图的模式；否则该工具不满足本轮默认路线，先更换入口或模型。

例如方舟将参考生成与首尾帧生成区分为不同任务模式，参考模式中写“以某图结束”也不等于硬性端点约束。[方舟官方接口说明](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)

## Run 视频提示词

先试 12 秒四方向视频，每段约 3 秒。时长和以下分配属于制作目标，实际有效区间需要人工确认；每方向至少有一个完整左右腿周期，优先保留两个以上供挑选。若不够，延长任务，不用减少完整步态来凑四方向。

| 目标区间 | 方向 | 每段内容 |
| --- | --- | --- |
| 0 至 3 秒 | 下 | 短站姿、迅速起跑、稳定原地跑步、快速收步并站稳 |
| 3 至 6 秒 | 右 | 同上，固定右朝向 |
| 6 至 9 秒 | 上 | 同上，固定背面朝向 |
| 9 至 12 秒 | 左 | 同上，固定左朝向 |

每段主要时间留给稳定跑步；站姿、起跑和收步只占短时段。不能保证模型严格按秒执行，因此不用目标时间表直接盲切。

### 可复制的 Run 模板

将引用标记、背景色以及角色装备说明替换成实际内容。装备说明采用基准图已确认的事实，不临时添加设计。

```text
制作一段用于游戏逐帧动画提取的 12 秒视频。

参考关系：图片1、图片2、图片3、图片4是同一个角色，分别对应朝下、朝右、朝上、朝左。
它们是同一角色的不同视角，不是四个人。任意时刻画面中只出现一个角色。
每个方向的外观、服装、装备归属、身体比例和俯视程度，以对应参考图片为准。
本次不新增服装、道具或装饰，不改变角色画风。

画面：使用参考图已经确认的游戏俯视视角。全程固定机位、焦距与构图。
人物在同一画布位置原地运动，保持统一比例和地面参考位置，完整入镜并为衣摆与装备留出边距。
允许正常跑步的身体起伏、腾空、摆臂和衣摆运动，不让角色在画面中整体走远或变大变小。
背景为均匀纯色 #00FF00，无地面纹理、投影、文字或分屏。

方向安排：
0至3秒：参考图片1，面向屏幕下方，展示正面跑步。
3至6秒：参考图片2，面向屏幕右侧，展示右方向跑步。
6至9秒：参考图片3，面向屏幕上方，展示背面跑步。
9至12秒：参考图片4，面向屏幕左侧，展示左方向跑步。
方向之间直接切换，不表演旋转、转身或镜头绕行。

每个方向段：从对应参考站姿短暂开始，迅速进入自然的大幅度原地跑步，
主要时间保持稳定节奏，重复完整的左右腿交替周期；最后快速落脚回正，
回到对应参考站姿并短暂保持。收尾不要继续迈出多步或产生整体滑行。
身体、头发、衣服和装备按运动自然响应，同时保持角色结构和装备归属一致。
```

第一次不上传动作参考视频，不补动作关键帧。先判断四方向、外观与完整周期是否可用。只有动作持续失败时，才另行评估增加动作参考，不能每次失败都堆叠新要求。

若四方向稳定跑步可以完成，但加入四次收尾后明显损害主体动作，保留相同参考图，删除“每段回站姿”的要求重试，将这一批标记为 loop_only。不要为了收步牺牲基础 Run；停止时使用后文的明确降级规则。

## 其他动作生成什么

先完成 Run，再按玩法需求增加动作。各动作始终传入相同版本的四方向 Idle，不额外生动作关键帧；沿用方向顺序和画面约束，替换动作段说明。

| 动作 | 替换后的动作要求 | 成品 |
| --- | --- | --- |
| Idle | 不生成视频，直接使用四方向基准 PNG | 每方向一帧 |
| Walk | 每段迅速进入稳定原地行走，完整交替左右腿，末尾短收步回站姿 | 每方向一个循环，收步可选 |
| Attack | 每方向从站姿开始，预备、完成一次指定攻击、收招、回站姿；不附带其他招式 | 每方向单次动画，标记命中时刻 |
| Jump | 每方向从站姿开始，起跳、腾空、落地、站稳；镜头和地面参考不动 | 每方向单次源动作，标记起跳、腾空、落地 |

Attack 提示词必须补充实际攻击方式和使用哪件武器，避免只写“攻击”。动作超出方向段时长就延长视频。Jump 的游戏落地时机由游戏逻辑决定，腾空阶段需要允许保持或循环；不能用视频总时长决定物理落地。

## 视频验收与方向分段

生成完成后先检查原视频，不急着抽少量成品帧。

1. 四个方向是否齐全且朝向正确，是否只有一个角色。
2. 对照对应 Idle 检查比例、视角、衣服和非对称装备，有没有消失、换边或变形。
3. 每方向是否存在足够长的稳定动作，Run 是否包含完整左右腿周期。
4. 人物是否被裁切，有无运镜、尺度漂移或严重背景污染。
5. 收尾是否存在，是否能回到对应 Idle 附近；这项决定是否有收步候选，不代替 Run 验收。

在时间轴上人工标记每方向的实际起止，以及稳定跑步区间和可选收步区间。保留转向或切换帧的源数据，但排除在有效动作之外。四方向生成有缺失时，仅补失败方向是返工手段；不重做已通过的方向，也不将缺失素材标为通过。

## 解码与帧整理

按源视频时间戳完整解码，再选择有效帧；可变帧率素材先记录时间或统一分析时间轴，不能直接用帧号除以猜测帧率。保留原视频、原帧和去背景后的帧，以便回查。

去背景后，统一不同方向、Idle 与移动动作的工作画布、缩放和地面锚点。先确定共同的安全边界，再应用同一套变换，不对每帧按包围盒重新缩放，也不把每帧最低像素强制贴到同一条线。

明显的整体漂移可以按躯干等稳定区域辅助校正；跑步正常的升降、前倾、脚腾空和衣摆摆动需要保留。角度、比例或装备结构本身错误的帧不能靠对齐修复。

在较高工作分辨率下选循环、整理动作，最后再统一缩到游戏尺寸。像素化不会自动修复轮廓闪烁，缩小后必须重新检查头发、剑、葫芦和透明边缘。

## Run 循环提取与方向对齐

### 先找完整周期

仅在稳定跑步区间内找候选，排除起跑和收步。选择包含左右腿完整交替的一圈，不能只因两个姿势很像就接受半周期。

候选需要同时满足：首尾姿势接近、接缝运动趋势连续、内部无坏帧、衣摆和挂饰没有明显跳变。可用主体轮廓和运动信息辅助排序，但第一版由人确认最佳候选。

若源帧 40 与 64 对应同一步态阶段，使用半开区间 [40,64)，不同时保留两个端点。Run 的首帧为稳定跑姿，尾帧为下一次同阶段到来之前的一帧，两者都不要求是 Idle。

### 再统一阶段和时长

对四方向分别标记“角色自身左脚接触地面”等阶段。屏幕左右不等于角色自身左右，尤其要检查前后视图。统一阶段起点和周期时长，必要时同时约束左右脚半周期，避免只旋转序列起点后内部阶段仍不对应。

成品可先试每周期 8 帧。假设一圈为 0.6 秒，8 帧应总共播放 0.6 秒，而不是直接沿用源视频 FPS。具体周期和帧数按观感确认，不能为凑 8 帧丢掉一个步态阶段。

优先选择最接近目标采样时刻的源帧。只有普通重采样明显卡顿时，才尝试本地 RIFE；在同方向相邻、结构一致的画面之间插值，检查双腿、透明边缘和装备，失败则退回源帧。不能跨方向、跨巨大姿势差插值。

换向时保留归一化步态进度，例如 run_right 的 40% 切到 run_up 的 40%。Walk 与 Run 切换也依据已标记的步态阶段，不直接假设相同帧号就是同阶段。

## 从同源视频提取收步

### 收步是附加产物

Run 基础成品是循环。视频中存在“逐渐减速跑几步再站住”，不代表该段适合本项目：松键后世界位置必须立即停止，因此只挑最后短促的落脚、重心回正与稳定站姿，排除多次继续迈步和整体滑行。

以约 0.1 秒作为初始观察目标，不作为固定合格阈值。时长最终由动作和目标帧率决定；不能靠简单加速让不合适的收步勉强通过。

收步最后必须能自然接到冻结的对应方向 Idle。若只接近但仍有明显衣摆、手臂或装备跳变，就调整截取或不启用；不能擅自替换标准 Idle 掩盖问题。

### 给每个 Run 帧建立可选入口

对最终导出的 Run 帧逐一检查，是否能当场接入某个收步帧及其后续片段。比较姿势、接缝前后的运动趋势、位置、比例、衣摆和装备；不能只看双脚。

保存最小映射：

```text
Run 第0帧 → 无匹配，直接 Idle
Run 第1帧 → Stop 第0帧及后续片段
Run 第2帧 → 无匹配，直接 Idle
……
```

映射必须在实际尺寸下播放验收。“最相似”不等于通过；没有匹配就留空。每个候选入口都要检查跳变和是否原地多跑，匹配不合格不阻塞 Run 导出。

若当前 Run 帧与 Stop 入口帧相同或近似相同，从 Stop 下一帧开始，或扣除入口已显示的时长，避免接缝重复停一拍。该处理也要随入口一起验收。

Walk 采用相同方法，但独立提取自己的同源收步并保存映射，不能直接套用 Run 的 Stop 或入口表。某动作没有合格收步时，该动作停止就直接 Idle。

### 运行时停止规则

```text
移动输入从有变为无：
    当帧停止世界位置移动
    读取当前动作、方向和 Run 播放帧
    有已通过的收步映射 → 当帧播放对应 Stop 后缀
    没有映射           → 当帧显示对应方向 Idle

Stop 播完：
    保持对应方向 Idle

Stop 中重新出现移动输入：
    当帧恢复移动并切入目标方向 Run 或 Walk
    使用已验收的恢复阶段；没有则使用该动作默认阶段
    不等待 Stop 播完
```

多个键同时按下时按合成移动输入判断。仍按 W 只松开 D，不触发收步。输入归零后不继续播放 Run 来等入口，也不等待一整圈，不为收步增加世界位移。

一段收步不能保证覆盖任意 Run 姿势。映射为空时直接切 Idle 是明确的视觉降级；若切换跳变不满足项目观感要求，该方向的停止效果仍未通过，不能以“成功导出”宣称完成。先保留可用 Run，针对失败区间返工；不默认增加额外关键帧或一套独立收步生成任务。

## 状态切换最小规则

| 输入或事件 | 行为 |
| --- | --- |
| 无移动输入 | 保持最后朝向 Idle |
| Idle 中开始移动 | 位移立即响应，进入目标方向 Run 或 Walk；不强制播放 Start |
| 移动中换向 | 方向瞬切，保留对应步态阶段 |
| Run 与 Walk 切换 | 按输入即时切换，并使用步态阶段映射 |
| 移动输入归零 | 位移当帧停止，有匹配短收步则播放，否则直接 Idle |
| 收步中重新移动 | 当帧中断并恢复移动 |
| 攻击输入 | 第一版原地播放完整攻击，命中由阶段标记触发；结束后读取当前输入恢复 Idle 或移动 |
| 跳跃输入 | 播放起跳，物理腾空时显示腾空段，实际落地后播放落地段，再读取当前输入 |

Attack 收招和 Jump 落地已包含在各自源动作中，不套用 Run 的收步片段。Idle 变体、复杂连击取消和独立 Start 留到基础流程通过后再决定。

## 导出文件与制作记录

每个角色保留如下最小结构。这里是素材目录约定，不要求第一版实现专用数据库。

```text
character_v1/
  idle/                 四方向标准 PNG 与 review 总览
  source/run/           原视频、实际参考清单、提示词和模型参数
  work/run/             方向区间、候选循环和工作帧
  export/               透明图集与 animations.json
  review.md             验收结果、失败方向和收步覆盖情况
```

动画描述至少保存：

| 数据 | 用途 |
| --- | --- |
| 角色基准版本、动作和方向 | 保持来源明确 |
| 图集位置、帧区域、每帧时长、循环标记 | 正确播放，避免丢失周期速度 |
| 统一画布和锚点 | 切动作不跳位置 |
| 源视频区间、采样帧与步态标记 | 回查和重采样 |
| 可选 Stop 帧和 Run 入口映射 | 只在已验收阶段启用收步 |
| 攻击命中时刻、跳跃阶段 | 支持玩法事件 |

收步入口映射必须针对最终 Run 帧生成；重采样、调序或修改 Run 后，重新验收相关映射。保存任务的实际输入和参数；固定种子若可用仅帮助复现，不能保证跨任务一致性。

## 首轮验收和返工

第一轮只做四方向 Idle 加一条四方向 Run 视频，收步按可用性附带。通过后再增加 Walk、Attack、Jump。

| 检查 | 操作 | 通过条件 |
| --- | --- | --- |
| 方向与外观 | 对照四方向 Idle | 方向齐全，视角比例正确，装备归属不变 |
| Run 循环 | 连播与慢放 | 完整左右步，接缝与内部无明显停顿、变形和闪边 |
| 换向 | 同阶段切四方向 | 比例、锚点与步态保持协调 |
| 松键 | 在 Run 每一帧分别松键 | 世界位置当帧停止，记录收步或直接 Idle 的实际效果 |
| 再启动 | 在 Stop 每一帧重新按键及换向 | 不吞输入、不等待，姿势切换可接受 |
| 最终尺寸 | 缩到游戏尺寸反复播放 | 头发、衣摆和装备可读，不出现明显原地蹬步 |

外观错误回到视频生成；循环不合适先重选区间；缩放锚点错误回到帧整理；收步不匹配则禁用对应映射。不要因为某项失败就重做整套角色，也不为了补一个收步改变已经通过的四方向基准。

第一版允许人工分段、选周期和验收入口，先完成一个角色的完整闭环，再考虑自动化。G-Studio 现有切图、去背景、图片预览和导出可作为基础；视频时间轴、循环分析、步态与收步映射需要后续实现或借助外部本地工具，现有图片区域 JSON 不能直接表达完整动画关系。
