# 模型、图片检查与优化缓存

模型查看的半透明叠加、差异图始终比较真实图片与模型，使用固定图片参考框和校准相机。左侧“滑动对比”默认打开，左侧显示原生模型与图片，右侧显示优化模型与图片。关闭滑动后，检查当前模型卡片采用的版本。效果预览用于图片打光，也共享滑动设置。

生成参数中的“生成后优化模型”默认开启。生成任务先接收原生模型，再运行优化，双方结果都保存成功后才发布完成；关闭此选项则跳过优化步骤。该设置随提交快照固定，不受任务运行期间的设置更改影响。生成后处理独立于视口，即使不打开结果也会完成。

打开场景、部件编辑器或历史结果永远不会启动优化。模型卡片的“使用优化结果”切换已有版本；仅用户明确开启且没有结果时才手动补算。错误如实展示，失败任务不会标记为完成。内置六个模型必须携带原生与预计算优化结果；缺失打包结果时报错，不通过启动时计算补齐。

缓存键包括模型内容摘要、图片像素摘要、图片尺寸、固定参考框及算法版本 model-fit-v3。名称、部件 ID、菜单展开与查看方式不参与计算。等价图片在内置 URI、PNG 数据 URI 之间转换不会重复优化。部件保存携带原生与优化快照，独立缓存也保留完成结果及选择。

PartAsset.model 是实际采用模型；modelComparison 保存原生、优化结果与选择。PartModel.id 唯一标识不可变快照，sourceModelId 表示优化结果的来源。mesh.modelId/modelRevision 追踪生成来源，后台重新生成不覆盖已采用快照。

内置六张图片使用 hunyuan-mini 生成的 GLB，来源与参数在 public/scene-lighting/models/manifest.json。优化结果随 optimized.json 分发，打开默认素材无需重新计算。新图片的 model.kind 为 none，等待 AI 生成；不提供模板、轮廓挤出或其它算法模型选项，也没有旧格式迁移。

模型下拉菜单只为可见卡片按需准备预览，共享一个 WebGL 上下文，以 24 帧/秒自动旋转。缓存最多 48 张首帧图片以加速重开，GPU 预览保留最多 8 个模型；移出可视区域、关闭菜单或页面进入后台时停止旋转。系统要求减少动态效果时显示静态预览。优化勾选框位于卡片右下角，生成入口是同尺寸的加号卡片。

视口底部由同一个提示元素显示操作说明或差异图颜色说明，切换模式只替换文字。

业务代码与文案统一使用“模型”。Three.js 的 BufferGeometry 和 mesh.geometry 是外部 API，保留其规定名称。
