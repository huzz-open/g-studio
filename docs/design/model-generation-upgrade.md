# 几何模型与推理服务改造方案

状态：几何接入与服务改造已实施；本机真实推理已验证，质量缺陷与硬件边界保留，未标记为全面验收通过。最终范围和未验证项见 [2026-10-28 验证记录](../history/model-generation-upgrade-20261028.md)。整理日期：2026-10-28。代码核对基线为 `dc96456` 及本次随文档提交的改动。第 2–3、10 节保留改造前事实与历史核查范围；本轮完成状态见第 11 节，不将历史结果替代当前验证。

## 1. 目标与范围

- 保留 Hunyuan3D-2mini-Turbo，新增 Hunyuan3D-2-Turbo 和完整规格 Hunyuan3D-2.1 Shape。
- 在生成速度、容量和几何质量之间提供明确选择，重点比较粘连、镂空、薄片、细杆及隐藏面的表现。
- 容量足够时启动后主动预加载、常驻复用，减少首个任务等待和连续任务重复加载。
- 接口可用性与模型就绪状态分离；加载过程中允许查询和提交排队任务。
- 启动时确定推理设备及每个启用模型的运行策略，任务执行期间不自动更换设备、模型或策略。
- 服务端返回模型定位及推荐标签，启动打印当前配置表，每次任务打印结果和耗时。
- 本轮只处理几何。Paint/PBR、文生图、2.1 Small、多视图模型及 MLX 后端不列入本轮必须交付范围。

2.1 是质量优先的升级候选，标准 Turbo 是速度与效果均衡的候选。两者是否改善现有素材的问题需要实际对照，不能将版本升级等同于消除粘连。单图没有提供的结构仍可能推断错误。

前四项 SHA256 已在两份模型清单中记录。2.1 Shape 官方元数据给出的 SHA256 为 `6b519fc7242f78e9b5f47ea4d55668fe3d944a2d27332f4ca68d29a6ff603f5e`，本轮已写入 `model-manifest-2.1.json`，完整下载文件的 SHA256/大小均通过校验。

2.1 官方加载代码从该 checkpoint 读取模型、VAE 及可用的 conditioner 权重；这条形状推理路线不预先重复下载独立 VAE。资源准备后必须检查实际组件、形状和配置是否完整匹配，禁止遗漏图像编码器后用随机初始化参数推理。发现额外资源需求时，先补齐固定版本清单，再实现加载。代码中的 FlashVDM 解码接口并不代表已经存在官方 2.1 Turbo 蒸馏权重。

资源沿用 `runtime/generation/models/`，推理源码放在 `vendor/`，平台依赖放在 `platforms/`。配置和已校验的权重可复制复用，平台二进制依赖不能跨架构直接复制。2.0 与 2.1 使用各自固定的源码及适配层，不能默认现有 2.0 source wheel 覆盖 2.1。

名称约定：仓库 ID 与模型子目录分开记录。`hunyuan3d-dit-v2-0-turbo` 是标准版形状网络的子目录；DiT 表示 Diffusion Transformer，VAE 负责解码几何。标准版 Turbo VAE 使用 3072 个 latent token，现有 Mini Turbo VAE 使用 512 个；权重、缩放参数及预处理配置不得混用。

## 5. 启动、容量和常驻策略

1. 服务接口先开放，健康检查代表 HTTP 服务可用，不等待大权重加载。
2. 后台完成设备检查、资源校验和容量评估，再确定启用模型的运行策略。
3. 常驻模型主动加载到选定设备，并执行有边界的预热；加载/预热不占用 HTTP 事件循环。
4. 加载完成后复用同一实例。不能每个请求重建 Pipeline 或重新读取权重。
5. 容量不足的启用模型明确使用分阶段/卸载策略，状态和日志如实说明，不能声称其已完整常驻。

容量依据包括实际可用系统内存、可用计算设备预算、精度、加载瞬时峰值、推理中间张量、并存模型及系统预留。统一内存不能按系统内存和显存相加；磁盘 FP16 权重大小不能直接当成 FP32 运行占用。尚无可靠的通用容量阈值，需用实测制定保守估计和显式配置。

三个模型都已下载不代表三个都能常驻。实现必须明确启动时的启用集合和每个模型的策略，对全部常驻实例做合计预算；容量不足时不能在后台循环淘汰、重载模型来伪装常驻。不采用首轮结束后自动调策略。

推理设备在启动时确定为 CPU 或 GPU；GPU 后端另记 CUDA/MPS。显式指定不可用设备时应清楚报错；自动检测模式可在启动决策阶段选择可用设备。执行期间错误直接使任务失败，不切换 CPU、不自动重试为其他模型，也不永久改变后续任务策略。

常驻加载可减少加载等待，但首次内核初始化及不同输入尺寸仍可能带来开销；预热是否充分需计时验证，不能承诺首个任务与后续任务耗时完全相同。MPS 先沿已验证路径适配；mmgp 的 CUDA 内存管理不能直接当作通用 MPS 实现。

## 6. 就绪状态、排队与取消

服务可用与模型状态是两个维度。模型状态应区分资源缺失、准备/加载、就绪、失败；具体字段命名在协议实现时确定。

- 启用且正在准备/加载的模型允许提交任务，返回任务 ID 和排队状态；资源未启用或准备失败的模型明确返回原因。
- 所有同模型请求共享一次准备过程。请求到来不重启、不取消、不复制该模型的加载。
- 队列有容量上限；超限返回明确错误，不能创建无界任务或并发加载。
- 模型加载完成后自动执行等待任务。尚未就绪的任务不能阻塞健康检查、状态查询或取消接口。
- 取消排队任务只取消该任务，不能停止公共预加载。取消正在运行的任务需有独立的中断边界；不能直接复用“杀掉进程即清空常驻模型”的旧实现。
- 加载失败需要结束或拒绝受影响任务，不能永久排队；其他已就绪模型和服务接口仍可用。
- 保持单任务推理并发作为初始实现，避免多个请求同时使用共享 Pipeline 的可变状态。
- 服务退出时清理工作单元，重启后未完成任务保留明确的 interrupted 语义。

协议类型、JSON Schema、OpenAPI、解析验证器、后端 submit 门槛、前端 `canGenerateModels` 和连接提示需同步修改。仅让服务端接收排队、但前端仍禁用提交，不满足要求。

## 7. 模型列表标签

标签由服务端根据模型定位、设备条件和已验证数据返回，前端本地化显示。中文控制在两个字以内，模型状态另行展示。

| 标签 | 含义 |
| --- | --- |
| 推荐 | 当前设备及启用配置下优先建议的模型；至多一个，没有依据时可不标 |
| 快速 | Mini Turbo 的速度侧重定位 |
| 均衡 | 标准 Turbo 的定位 |
| 精细 | 2.1 Shape 的细节侧重定位，不保证每个样例都更准确 |

加载中的可用候选仍可显示定位/推荐标签并接受排队；失败或未启用模型不标推荐。不能只看 GPU 名称推荐最大模型，也不宣称没有测量过的速度倍数或质量排序。新增字段要兼容旧服务不返回标签的情况，不能因标签缺失导致连接失败。

## 8. 日志要求

启动输出“类别 / 当前值 / 备注”三列表格。展示操作系统、处理器、显卡、系统内存、推理设备、计算后端、精度、模型、运行策略、FlashVDM 状态和服务地址。只打印检测到的真实值；未知值标未知，不编造可用显存。多个模型采用明确的多行，不能用一个策略掩盖差异。

推理设备只有一个当前取值，不同时列 CPU 主用/GPU 备用。接口开放与模型加载完成分别记录，避免误解“服务就绪”为“所有模型已加载”。不将真实访问凭证复制到文档或测试报告。

以下仅为格式示例，不是实测数据：

```text
[生成服务] 接口已启动
[模型] 标准 Turbo 开始加载
[任务 a12b] 已排队，等待模型就绪
[模型] 标准 Turbo 加载完成
[任务 a12b] 开始生成
[任务 a12b] 完成 | 总耗时 92.3 秒 | 执行 84.5 秒
```

每次任务都打印开始与完成/失败/取消结果。总耗时从接收请求计起，包含排队和等待；执行耗时从实际开始任务计起，分阶段模式中的该任务加载开销也应计入。使用单调时钟计时。失败显示原因和耗时，不打印自动回退或首次任务后换策略的信息。

## 9. 实施顺序与验收

1. 先校验本次携带但未完整核实的安装、连接和网络改动。
2. 准备第 4 节权重及配置，复用正确缓存，检查 checkpoint 组件，补齐 2.1 固定源码与依赖清单。
3. 引入模型描述/适配层，注册标准 Turbo、2.1，保持现有参数和历史任务兼容。
4. 实现独立加载工作单元、启动预加载、常驻实例复用和固定运行策略，移除运行中自动回退。
5. 同步就绪状态、加载期间排队、取消语义、前端标签及三列表格日志。
6. 完成自动测试与真实推理对照，并记录环境、模型 revision、精度、步数、分辨率和计时边界。

必须覆盖的行为：

- 加载故意延迟时，健康、能力、提交、查询、取消接口仍及时响应。
- 并发提交只触发一次模型加载；第二个及后续任务使用相同常驻实例。
- 取消排队任务不打断加载；取消执行任务不会错误取消其他任务或隐式重复预加载。
- 加载失败、推理 OOM、无效输出和退出都能结束对应任务；设备/策略不会被自动改写。
- 多模型总预算、资源缺失、离线启动、重复启动、模型切换及旧服务无标签的兼容性。
- 模型、配套 VAE、输入预处理、latent token、缩放参数和采样器匹配。
- 同一批花瓶、镂空椅子、细杆和复杂装饰素材对比三个模型，检查最终减面结果；成功导出文件不等于几何质量通过。
- 分别报告首次准备、后台加载/预热、任务排队、任务执行、连续任务以及峰值容量；不能拿不同设备/参数的历史数字算加速倍数。
