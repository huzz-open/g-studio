# 正交相机配准与三维投影渲染

生成完成后的配准与部件编辑的优化开关现在调用 `optimize-model.ts → registration-client.ts → registration.worker.ts → camera-registration.ts`。旧的自由三轴旋转、可见面回退及轮廓裁剪不再属于新生成流程。历史实验见 `../history/camera-registration-validation-20261031.md`。

## 数据和几何

`PartModel.registration` 保存参考相机俯仰、方位、像素尺度、像素平移和参考图片尺寸，方法名为 `orthographic-camera`。新结果不保存 imageFit 或 repair。缓存使用独立的方法键，不迁移旧优化配方。

所有输入使用同一参数域：相机俯仰 5°～80°，水平角完整一周、统一尺度及图像平移。不按物品名称选择规则。5° 下限避免接地深度计算在水平观察时退化，80° 上限避免接近垂直俯视的坐标奇异性。

`registered-model.ts` 将参考方位转换为绕世界 Y 轴的水平转向，保持原模型的上方向；将像素尺度换算为世界统一尺度，计算平移，并沿参考视线平移到最低点接地。不会压扁、剪切、俯仰、侧倾或改变三角形拓扑。源 GLB 不变，显示与阴影使用同一组处理后顶点/三角形。接地依据是最低点，不代表已推断物理支撑面。

## 显示与光影

每个配准资产使用自己的参考基向量烘焙深度和法线。配准后的效果预览使用网格上的原图投影纹理，光照计算使用实际三角形世界位置与法线，避免继续把图片当成固定 20° 平面，同时让阴影使用另一份几何。

场景相机是共享状态 `cameraPitch`，保存到场景并进入撤销/恢复。向空场景添加首个已配准资产时采用其参考俯仰角；之后不会为其他资产偷偷切换全局相机。不同来源视角的素材在共同相机下会重新投影，不能承诺同时与各自原图逐像素相同。只从一张图做投影纹理也不能提供隐藏面的真实纹理。

部件编辑和模型生成共用相机参数编辑：参考俯视角、水平朝向、投影比例和 X/Y 偏移。编辑采用候选并存储其参数；相机轨道操作不写入模型参数。参考视角重置使用配准俯仰角。取消优化终止 Worker，不写入候选；生成的源数据在异步操作结束前发生变化时，调用方拒绝采用旧结果。

## 自动化边界

自动部分目前仍使用轮廓与双向轮廓距离，不是自动二维—三维语义对应求解器。已知薄片和对称结构存在多个相似投影，本版本提供参数编辑处理这些资产，不能把这些多解宣称为已经自动消除。之前有真值实验中的 oracle 对应点求解器仍仅用于测试。

## 验证

- `npm run test:registration`：相机坐标、独立光栅器、已知对应参考解、保形/保竖直、接地、顶点与三角形一致、正交歧义、场景相机序列化。
- `npm run test:parts`、`npm run test:scene-lighting`：现有部件和光影回归。
- `tests/production-registration.e2e.cjs`：实际真实伞模型的 Worker 配准、取消、不可变原始模型、新参数编辑、WebGL 显示、保存与刷新。
- `node scripts/registration/build-bundled.cjs`：从清单中的原始 GLB 和 PNG 重算六份默认配方，不以旧配方为输入。

新自动路径已接入产品，但“任意生成模型与原图的唯一正确自动对应”仍是未解决的算法边界，不能把工程接入或测试通过当作该问题的证明。
