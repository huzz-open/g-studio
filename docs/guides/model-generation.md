# 使用模型生成

返回[文档索引](../README.md)。本页说明网页操作；安装、硬件和缓存见[后端部署](../../services/generation-python/README.md)。

## 选择运行方式

| 场景 | 启动方式 | 网页连接 |
| --- | --- | --- |
| 只需轮廓近似 | 在线体验或 `npm run dev:web` | 不需要服务 |
| 本机网页与 AI | `npm run dev` | 直连接口 |
| 已有网页，只启动 AI | `npm run dev:gensvc`（或 `sh start-generation.sh`） | 直连接口 |
| 还没有后端源码 | 在设置中复制当前站点的安装命令，到生成设备的终端执行 | 填写终端打印的地址和凭证 |
| 浏览器和生成设备不在同一台电脑 | 后端加 `--host 0.0.0.0` 和允许的 `--origin` | 填写生成设备实际 IP 或可达的 HTTPS 地址 |

首次 AI 启动会下载运行环境和模型；已有完整资源会复用。当前使用最新源码加镜像启动。只使用本机 CPU 时，在项目目录执行 `npm run dev:gensvc -- --cpu`（或 `sh start-generation.sh --cpu`），会完成准备并启动服务；使用 NVIDIA CUDA 时执行 `npm run dev:gensvc -- --cuda`。已有 Node/npm 时可先执行一次 `npm run setup:cn` 使用国内镜像。首次准备不要加 `--offline`。启动服务不会自动上传图片，也不会把默认轮廓近似切换成 AI。

`npm run generation:download` 用于仅准备环境和模型资源，`npm run generation:doctor` 用于检查环境、设备及服务连接；这两个命令不会启动生成服务。

## 连接本机服务

1. 启动后端，等待日志显示服务已就绪。
2. 在 **设置 → 模型生成 → 连接服务** 填写 API 地址和访问凭证。初始未配置时会展示安装引导，不会自动请求本机 API；无需切换连接方式。
3. 点击“测试连接”，检查计算设备显示为 CPU 或 GPU。显式填写本机开发 API 地址后，可自动取得本机连接凭证。
4. 下拉列表以标签显示“已启用／未启用”；未启用项仅供查看，鼠标和键盘均不能选择。旧选择被服务端停用时，会切到已启用模型；全部未启用时显示中性“未启用”状态。启用状态与运行失败分开，已启用但加载失败的模型仍可选择并查看错误，不会自动替换成其他模型。加载中可以提交排队，取消排队任务不会中断公共加载。失败时可悬停状态查看原因或检查后端日志。

生成入口、测试结果和设置状态统一反映生成服务是否可用。接口可访问但模型失败时仍显示“失败”，悬停可查看原因。内存或显存预估不足不会拦截加载和生成；仅在实际执行发生 OOM 等错误时报告失败，不自动切换设备、模型、精度或策略。模型加载失败后需重启生成服务才能重新加载；测试连接只刷新状态。任务执行失败可在处理原因后手动重新提交。

在线网页访问本机服务需要配置允许的网页来源、直连凭证，并可能需要浏览器本地网络权限。具体配置见[公网网页连接](../../services/generation-python/README.md#public-websites)。

## 计算设备与支持范围

| 设备 | 当前行为 | 验证范围 |
| --- | --- | --- |
| Windows x64 CPU | 完整 CPU 推理与缓存启动 | 历史 Mini 真实生成与搬移已验证；新多模型 CPU 路径本轮未实测 |
| Windows NVIDIA | 使用 CUDA 12.4 / PyTorch 2.6.0；启动确定设备，执行失败直接报告 | 可在 CPU 电脑准备 CUDA 依赖，实际显卡推理需对应硬件验证 |
| Mac M 系列 ARM64，目标 macOS 14+ | 自动模式启动时优先 MPS；采样/解码默认 FP16，Mini 图像编码固定 FP32；执行期间不切换设备 | Apple M5（24 GB、macOS 26.5.2）本轮真实运行与原始/减面检查见验证记录；仍有质量限制，其他 Mac 待验证 |
| Windows Intel / AMD 显卡 | 使用 CPU | 暂不支持 XPU / ROCm 加速 |

当前模型不支持 NVIDIA GeForce MX150（2 GB）的 GPU 推理，请使用 `--cpu`。

连接成功后，界面会显示实际使用的 `CPU`、`GPU · NVIDIA CUDA` 或 `GPU · Apple MPS`。普通“有显卡”不等于当前模型能使用该显卡；驱动、PyTorch 构建和具体算子都要匹配。模型权重没有改变，适配的是执行这些权重所需的运算后端。显式指定不可用设备会报错；任务失败不会自动更换设备、模型或运行策略。输入预处理固定使用 CPU FP32，模型计算使用所选设备。

Hunyuan 推理源码由仓库内已校验的 wheel 提供，权重和依赖由启动器准备。资源已准备完整时仍可用 `--offline` 禁止下载。硬件和强制设备选择见[后端部署](../../services/generation-python/README.md#gpu-and-platform-support)。

默认启用 Mini Turbo。标准 Turbo 和完整 2.1 Shape 可通过 `sh start-generation.sh --models all --mps` 启用（其他设备选择对应参数）。默认常驻运行，只有显式指定 `--strategy staged` 才分阶段加载；旧的 `--strategy auto` 参数兼容为常驻，不再按容量自动选择策略。仅启用一个模型时可用 `--models turbo` 或 `--models 2.1`。模型常驻时启动后主动后台加载并复用；分阶段策略会明确显示。当前验证与质量限制见[本轮记录](../history/model-generation-upgrade-20261028.md)。

## 安装并直连其他设备

在设置中勾选“允许其他设备访问”，复制安装命令到承担模型生成的电脑执行。安装脚本地址跟随当前站点的域名和部署子路径；它会下载并校验后端源码，再调用项目内启动脚本。重复安装保留已有环境、模型和凭证；已有源码的开发者直接运行：

```sh
sh start-generation.sh --host 0.0.0.0 --origin https://your-site.example
```

默认仅监听 `127.0.0.1`；`0.0.0.0` 允许通过网卡地址访问，但不能填作前端 API 地址。应填写终端显示的实际地址，例如 `http://192.168.1.20:8765`，以及访问凭证。请求从浏览器发出，网页部署在公网也不要求生成服务拥有公网 IP，只需浏览器所在网络能访问它。

本机及内网 IP 可使用 HTTP，公网 API 需要 HTTPS。跨域来源、凭证和浏览器本地网络权限仍需满足；网页开启 HTTPS 不会自动为生成服务提供 HTTPS。安装依赖、源码发布和自定义参数见[外部安装](../../services/generation-python/README.md#external-installation)。

## 独立生成与查看

1. 进入“模型生成”选择图片，左侧参数直接平铺，调整后点击“生成模型”。
2. 视口左上角的悬浮队列集中展示任务，点击展开或收起，选择任务可查看进度与结果。
3. 完成的模型自动保存在当前浏览器中，无需“应用结果”。即使服务断开，也能进入页面查看已保存的模型。
4. 在 3D 视口拖拽旋转、滚轮缩放、右键拖拽平移，双击或点击“重置视角”居中。底部可切换线框和原图对照。

独立生成不会绑定部件、跳转部件编辑器或修改场景。悬浮队列通过“展开 / 收起”切换，选择任务或切换标签不会重置展开状态。选中任务后，右侧属性栏只读展示任务状态、生成参数和模型信息；左侧回显所选模型的原图缩略图及尺寸，可直接使用该图再次生成。生成参数保留用户当前输入，不会被历史任务回填。

目标三角面数、随机种子和模型采样参数按部件或输入图片独立保存。在当前素材里修改参数不会改动其他素材或全局默认值；新素材从设置中的默认参数开始，替换输入图片会创建独立参数。部件参数保存在当前浏览器中，关闭面板或刷新后仍可恢复；场景中的快捷生成也使用该部件的参数。已提交任务保留提交时的参数快照。

重置按钮始终与参数原始默认值比较：目标三角面数为 12000、随机种子为 12345，采样步数和网格提取分辨率采用当前生成算法声明的默认值（当前为 5 和 256）。当前值不同时显示按钮，悬停可查看恢复目标；点击后恢复原始默认值。自定义初始化设置、素材保存值和历史生成参数都不会成为重置基准，旧版本保存的独立基准会被忽略，已有参数和生成记录仍保留。

## 在编辑部件时使用

在“场景光影”或“精灵图切分”的部件编辑器中，展开几何下拉菜单，点击首项“＋ 生成模型”。参数、进度和 3D 预览都在当前页面完成；任务同时托管到模型生成队列。关闭生成面板不取消任务，重新打开同一部件可找回关联记录。

预览满意后点击“应用到此部件”，仅替换当前部件草稿的几何，保留名称、法线和对齐参数；再保存部件完成修改。生成失败不会覆盖旧模型，源图改变后也不会应用旧图的生成结果。保存的部件网格可离线使用。

应用生成模型时默认使用原始生成网格，不自动校准，也不在打开部件编辑器时自动运行优化。点击“生成优化候选”后，在后台计算尺寸、朝向和位置；完成后只更新候选，当前采用的模型不变。左侧“使用原始模型 / 使用优化结果”决定实际采用的版本，保存后场景光照、阴影和导出的部件使用该版本，另一版本仍保留。已有保存的几何修改保持原有效果。

打开“滑动对比原始与优化”，水平拖动竖直分隔线查看左右差异。两侧使用相同大小的画布、相机、灯光、地面和场景位置，并用两个版本的联合范围统一取景。几何模式中拖动画面同步旋转，右键或 Shift 拖动平移；图片光照模式保持原图对应的固定视角。滚轮缩放同步，分隔线只改变显示范围；键盘方向键、Home/End、PageUp/PageDown 也可调节分隔线。

新候选不会覆盖已经采用的优化结果；取消、失败和不支持的几何修复保留已有候选与选择。图片或生成模型源改变后，旧候选不可再采用，已采用的网格快照保持不变；重新选择模型可开始新的原始/候选对比。候选意味着处理结果，不意味着更正确。理论及算法边界见[轮廓配准设计](../design/silhouette-registration.md)。

建议保留默认的 5 步采样和 256 网格分辨率。花瓶实测中，仅将采样改为 1 步就出现严重变形，且网格提取更慢；任务成功、GLB 非空不代表生成质量合格。

自动校准默认保护输入模型的既有可见表面，避免仅因轮廓分数更高就翻到背面。若最佳轮廓候选需要显著换面，会保留保守结果并提示检查几何视图；原始模型本来朝向错误时，可先手动确定正确可见面再校准。旧数据不会在打开时重新计算，明确的手动调整保留。此机制不修改网格孔洞或隐藏结构。

生成候选后可点击“按原图修复几何”：保留原图透明孔洞，裁掉透明区域多余的几何，只补齐有可靠邻域深度的小缺口。“启用几何修复”可切换前后效果；源 GLB 保留。模型、图片、尺寸或对齐改变后旧修复停用，需要重新执行。修复成功也只更新候选，需选择“使用优化结果”才采用；保存部件后，场景与可移植导出都携带已选版本和候选参数。修复基于当前固定相机，不等同于恢复不可见真实结构或生成已验收的碰撞体。

当前版本先检查网格是否满足封闭有向实体条件。检查不通过或切口不明确时会提示并保留原几何，不会提交部分裁剪。旧 v1 修复不再自动执行，需要重新检查。修复保留原图像素分辨率；超过 1,048,576 像素的工作预算时不会隐式降低精度。相同参数的源几何与已经验证的结果均可通过开关查看。

单张图片无法保证还原真实几何，瓶口、椅子间隙和不可见表面可能被填充。生成完成后仍需人工检查；实际样例与已验证平台见[验证记录](../history/model-generation-validation.md)。
